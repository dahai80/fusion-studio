## Track 2 — Local `swift test` = 0 (toolchain drift)

**Status: confirmed, NOT a regression. Gate documented.**

- `swift --version`: Apple Swift 6.3.3 (swiftlang-6.3.3.1.3), target arm64-apple-macosx26.0. macOS 26 (Darwin 25.6.0).
- `swift test list` enumerates **66 test entries** (331 lines output) — XCTest cases ARE discoverable for listing.
- `swift test` runs: "Test run with 0 tests in 0 suites passed after 0.001 seconds." Testing Library 1902. Execution discovers 0; listing discovers 66. This is the known Swift 6.3.3 / macOS 26 / Testing Library 1902 incompatibility — XCTest execution path not wired.
- **Authoritative gate**: CI (GitHub Actions, macOS-14 + Xcode 15.x) `swift test` runs ~204+ cases. Confirmed green on all v0.1.58 PRs (#400, #401).
- **Local build gate (TRUTH)**: `swift build -c debug` EXIT=0 AND `swift build --build-tests` EXIT=0. Both compile the test target — compilation succeeding means test code is at least type-valid locally even if execution is toolchain-blocked.

**Verdict**: No action required in code. Gate stays CI-authoritative. The `swift test list` (>0) + `swift build --build-tests` (EXIT=0) pair is the local proxy: if list drops to 0 or build-tests fails, THAT is a real regression to investigate. Documented in CLAUDE.md already.

**Risk**: a test could be broken (compiles, fails at runtime) and local toolchain would hide it. Mitigated by CI gate on every PR. Acceptable for enterprise beta; flag for toolchain upgrade tracking.
