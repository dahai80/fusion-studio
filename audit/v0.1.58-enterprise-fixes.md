- **~~Shared cluster token~~** RESOLVED — #77 per-leader token (X-Leader-Token header) wired in commit `3bd17e3`; server opt-in enforce (HA standby). Idempotency keys + write gate remain defense-in-depth.
- **~~JWT not signature-verified~~** RESOLVED (keyless mitigation) — local-first client still cannot HS256 verify (needs issuer secret), but `IdentityService.validateClaims` now performs keyless claim integrity checks: rejects `iss ≠ "fusion-identity"`, `aud ≠ "fusion-studio"`, `exp` past, `nbf` future; on tampered/expired/notYetValid clears identity + throws `IdentityError`. Server remains final authority (defense-in-depth, no secret on client). Commit pending.
- **~~Bundle manifest verify is warn-only~~** RESOLVED (opt-in enforcement) — `verifyBundleManifest` now returns `Bool`; default stays warn-only (no MANIFEST deadlock), but enterprise deployments can opt in via Settings → Supply Chain Integrity → `enforceBundleIntegrity` to reject the bundled backend on checksum mismatch and fall back to dev start.sh (no deadlock). Commit pending.
